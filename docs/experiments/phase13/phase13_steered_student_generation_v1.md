# Phase 13：由完整开发选择固定 B3/B4/B7 学生源

配置 `configs/phase13_unified_math_candidates_steered_v1.json` 扩展共用数学候选入口。它与 B0/B1/B2 使用相同的 6,723 题、顺序、32 个分片、每方法四个候选、采样流、4K cap、batch size 8 和 H100 路由，共预期 80,676 条真实候选。

配置中的方法强度在准备前保持未解析状态。准备只读取已完成 `unified_steering_analysis_v1` 的实际选择，核验其分析配置绑定，并重新执行已登记的准确率/覆盖/cap 筛选、配对长度目标和低强度平局规则。选中的方向文件、key、层位、prompt 和强度必须与开发 sweep 的实际配置完全相同；任何方法没有合格点时明确报错，不静默改成零强度或另一方法。

输入、方向和解析后的最终配置会写入新的冻结协议。所有候选与选择、完整池覆盖和成本继续复用 `unified_math_candidates` 的实现与审计。只有实际 H100 上的新 smoke 和合并完成后才可生成学生分片；开发集始终不作为训练监督。

16 项检查 `822630`、完整开发合并 `822340`、选择 `822401` 和学生源准备 `822631` 均已完成。实际冻结的 B3/B4/B7 分别为第 17 层 rho=0.2、第 16 层 ASC scale=0.5、第 17 层 rho=0.2；学生源协议的 26 项输入绑定及 442 项源码绑定通过，题序和共享设置与 raw stage 逐项相等。

H100 smoke `822746` 和审计 `822747` 已完成，共 96 条候选、峰值 allocated 16,945.18 MiB，生成 406.60 秒、额外重放 79.56 秒。B3/B4/B7 在 smoke 上正确支持分别为 4/4/6 题，共同支持 4/8；这只是接口检查。32 个学生分片 `822748`–`822779` 和完整合并 `822780` 按成功依赖推进；首片 `822748` 已实际运行，其余等待资源或依赖，尚无完整学生源比较。完整调度记录保存在 `preparation/unified_math_candidates_steered_launch_v1/student_generation_dag_v1.json`。

八方法开发共同正确支持为 53/64，三个被选 steering 条件各为 57/64；这些是开发结果。相对各自与 B1 的 55 题配对支持，选中的 B3/B4/B7 最短正确监督平均分别减少 55.51/12.11/51.71 tokens。比较支持并非三方法完全相同，不能由这些数字直接作相互优劣排序，更不能当作学生学习收益。

开发阶段后续分片 5/7 的 `822337/822339` 在输出目录尚不存在、作业仍 PENDING 时改排 H200，并重新使用已释放的并发 lane，最多四个开发分片同时运行。原 L40S 分片继续完成，没有重启。初次合并更新返回 dependency error，但部分修改了 GRES；重新核对 Slurm 后，去掉已由实际产物验证的旧 smoke 调度依赖，第二次更新成功。两次调用与前后状态都保存在开发 launch 目录的 `pending_h200_reroute_v1/v2.json`，原始提交记录不覆盖。
