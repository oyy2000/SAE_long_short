# Phase 13 baseline reproduction

This branch implements ASC-CES, DAP rewriting, and TokenSkip-style distillation components. It does not inherit a claim of successful reproduction from the source audit. The current executable [method-check configuration](../../../configs/phase13_baseline_method_check_v1.json) uses previously observed GSM8K development questions; it is separate from the [7.5K/25K expansion plan](phase13_baseline_expansion_experiment_plan_zh.md).

## ASC-CES fidelity

The implementation in [asc_ces.py](../../../src/length_budget_distill/asc_ces.py) follows equations 1–9 and Appendix A of the [published paper](https://aclanthology.org/2026.findings-acl.1828/). It optimizes a single vector with Adam, learning rate 0.01, two calibration pairs per step, 3,000 steps, and no weight decay. The language model remains frozen. The loss is softplus of the difference between concise and verbose **mean** token NLL, plus `20 * max(KL(base || steered) - 0.02, 0)`. KL uses the full vocabulary on WikiText. A finite penalty does not guarantee that every minibatch or held-out average satisfies the budget; both are recorded.

The vector is added at the transformer block output. On prompt prefill it affects the last prompt state, which predicts the first response token. Subsequent decoding states also receive the vector. Teacher forcing applies the same state mask, excluding earlier prompt positions. Numerical tests compare this implementation with cached autoregressive decoding and check that the base model receives no gradients or weight updates.

The public ASC commit `27f02ed4a1a935cbe3a2736cc275ecf92e89ee0d` contains an older last-token activation-difference extractor, not this optimizer. That extractor is evidence for the separate B3 dense control; it is not used as a substitute for B4.

The method check makes explicit choices where the paper leaves details open: zero vector initialization, zero-based layer index 16, response EOS included in NLL, WikiText-2 raw training paragraphs with at least 64 words, 2,000 fixed sampled paragraphs, a 512-token general-text window, two generic examples per update, and 64 additional paragraphs for held-out KL measurement. One hundred calibration questions come from the existing training split; concise traces use official GSM8K references with calculator annotations removed. The verbose reference is the first correct uncapped candidate among the first four existing candidates that is longer than the concise reference. This reuse and selection must be replaced or explicitly retained in any later registered study.

The first GPU check uses Qwen2.5-7B-Instruct for the unified-teacher comparison. It is an adaptation, not a reproduction of the published R1 model scores. Both Qwen and R1 have complete 3,000-step fits and six-scale development sweeps. The [uniformly reviewed comparison](../../../results/phase13_baseline_expansion_v1/exploratory/asc_method_analysis_v3/report_zh.md) records Qwen correct counts 64/64/62/63/63/38 and R1 counts 59/59/61/60/56/4 at scales 0/0.1/0.25/0.4/0.5/1. All Qwen interventions increase mean length. R1 scale 0.25 changes length by −14.80 tokens, 95% paired CI [−34.92,+5.83], from a 417-token baseline; this does not establish compression. Full-strength R1 still averages 3,286.92 tokens with 20/64 cap hits. The current project-prompt setting has not reproduced the paper's compression effect. Earlier extraction-version reports remain archived.

## Execution and evidence

The small entrypoint [13_3_run_baseline_reproduction.py](../../../scripts/13_3_run_baseline_reproduction.py) runs one stage: preparation, ASC smoke/full fitting, ASC generation, DAP rewriting, or TokenSkip compression. [baseline_reproduction.py](../../../src/length_budget_distill/baseline_reproduction.py) reuses existing JSONL, hash, completion-marker, model-loading, and NCSU GPU-admission helpers.

Preparation runs on a Slurm CPU allocation. It binds input cohorts, model hashes, dependency versions, prompt contents, and a frozen code snapshot. GPU stages run from that snapshot, with explicit allocated-device checks. Each completed stage publishes per-example or per-step records, aggregates, and a hash-bound marker. Partial output directories remain failed/incomplete attempts; they must not be overwritten or interpreted as successful runs.

Acceptance proceeds in order:

1. Numerical objective, masking, frozen-weight, and ratio-conditioning checks pass.
2. Real 7B ASC smoke fit produces finite nonzero gradients and a valid vector; cached generation succeeds. DAP and LLMLingua-2 process the full registered development cohort.
3. Complete the 3,000-step ASC fit and measure development accuracy/length/cap-hit behavior at the frozen scales. Inspect held-out KL and DAP/TokenSkip behavior, including adverse results.
4. Complete checks on the published reasoning-model setting; freeze the expanded data and grading protocol.
5. Generate matched training supervision and run the registered student SFT comparisons, including actual TokenSkip ratio-conditioned training and inference. Only those results can support the distillation contribution.

The numerical tests and preparation alone do not complete any published baseline reproduction or the persistent research goal.
