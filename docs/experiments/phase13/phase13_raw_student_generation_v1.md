# Phase 13：真实学生题池的 B0/B1/B2 源监督

该阶段开始处理已隔离的 6,723 道 MATH 学生候选题。它们来自 7,500 题来源池，经过已登记的去污染、重复检查与角色排除；6,723 是生成前的问题数，最终正确监督共同支持需等全部八种方法完成后计算。

配置 `configs/phase13_unified_math_candidates_raw_v1.json` 复用 `13_29_generate_math_candidates.py`，写入独立的 `results/phase13_baseline_expansion_v1/formal/unified_math_candidates_raw_v1`。开发、校准与历史 pilot 产物仍保留在原目录。

## 固定内容

直接绑定已完成的 64 题 B1/B2 开发生成与选择标记、完整 MATH 角色、typed grader、教师 revision 和源文件哈希。新增注册检查要求主教师、采样、候选数、随机流、提示和选择规则与实际开发配置完全相同。当前注册只允许普通教师和简短提示的源生成，不在学生题池上重新选择 ASC/SAE/dense 强度。

每题 B1、B2 各四个候选，共 53,784 条预期输出；B0 从同一 B1 去重正确候选池中均匀随机选取，B1/B2 选择最短正确且未达 cap 的候选。保留完整候选、零支持题、每题随机种子、真实 token、GPU/批次成本，分别审计各方法覆盖和可用方法的共同支持。此处的 B0/B1/B2 交集不等于 B0–B7 最终训练集。

未干预 B1 是 DAP 和 TokenSkip 的共同源，因此这项源生成不需要等待 steering 运行点；文本压缩阶段仍需验证完整源合并。ASC、dense、SAE 在完成独立开发选择后生成同一学生题池。最终统一 SFT 需要全部数据、共同支持与训练协议，不能仅凭源生成完成启动比较。

## 调度与规模

32 个固定取模分片，每片 210 或 211 题；最多四个原始生成分片同时运行，使用 `sbatch` 成功依赖控制。先完成同设置 smoke 与合并审计，再运行学生分片，最后做完整候选格、重复/缺失记录、文本/token、评分与批次成本核验。

开发阶段实际 B1/B2 总生成时间为 1,195.34 秒。按问题数线性外推约 34.9 GPU 小时，仅用于排期；原测量使用 H200，主分片拟用 H100，吞吐和问题长度均可能变化。H100 每片请求八小时以覆盖尾部，仍记录实际消耗。所有启动均检查分配 GPU 的健康和显存，不把排队状态当作完成证据。
